## 2. 背景与目标

奶蛙 Python 学习平台的学生端（003）已经具备注册登录、课程学习、题库练习、学习记录、排行榜、消息、个人中心等能力，业务数据保存在 MySQL 数据库 `naiwa_learning` 中。

运营和教研人员需要一个**内部后台管理系统**，集中查看：

- 系统注册用户及其学习情况
- 课程、章节、课时、知识点与题库内容
- 用户的报名、学习记录、提交记录、每日统计、成就等数据
- 消息、收藏、推荐、每日一题等运营数据

目标：用最低成本实现一个**只读数据管理后台**，帮助运营快速检索和分析数据，不改变学生端现有业务。

## 3. 范围与硬性约束

### 3.1 硬性约束（来自课程要求）

1. **禁止修改数据库**：后台只允许执行 `SELECT` 查询，不允许 `INSERT / UPDATE / DELETE`。
2. **禁止修改数据库表结构**：不允许建表、改表、加字段、加索引等任何 DDL。
3. 后台必须基于现有数据库 `naiwa_learning` 的 30 张表与 5 个视图实现。
4. 不替换、不破坏 `003` 学生端现有功能。

### 3.2 因此确定的设计原则

- 后台是**纯只读系统**：所有业务页面只查询、不写入。
- 管理员登录**不写数据库**：凭据通过环境变量配置，签发短时效签名 Token，不写入 `users` / `sessions` 表。
- 不新增“管理员账号”数据，避免违反“禁止修改数据库”的要求。
- 所有列表查询使用参数化 SQL，只访问已存在的表和视图。

## 6. 功能需求

### 6.1 登录

| 项 | 说明 |
| --- | --- |
| 输入 | 管理员账号、密码 |
| 校验 | 账号与密码均来自后端环境变量；密码使用 bcrypt 哈希比对 |
| 会话 | 登录成功签发 HMAC 签名 Token，有效期 2 小时，仅保存在前端内存 / sessionStorage |
| 失败处理 | 连续失败 5 次锁定 15 分钟（进程内限流即可） |
| 安全 | Token 校验所有 `/api/admin/*` 请求；后端 CORS 只允许后台前端地址 |

页面元素：品牌区、账号输入框、密码输入框、登录按钮、错误提示。

### 6.2 数据概览

顶部 KPI 卡片（数据来自现有表）：

| 指标 | 口径 | 数据来源 |
| --- | --- | --- |
| 总用户数 | `users` 行数 | `users` |
| 今日新增用户 | `created_at >= CURDATE()` | `users` |
| 近 7 日活跃用户 | `user_daily_stats` 近 7 天去重用户数 | `user_daily_stats` |
| 课程数 | `status = 'published'` | `courses` |
| 课时数 | 已发布课时 | `lessons` |
| 题目数 | 已发布题目 | `questions` |
| 提交总数 | `submissions` 行数 | `submissions` |
| 全站通过率 | `accepted` 提交数 / 提交总数 | `submissions` |

中部图表：

- 近 7 日每日新增用户（`users.created_at` 按天聚合）。
- 近 7 日每日学习时长（`user_daily_stats.study_minutes` 按天求和）。

底部区块：

- 热门课程 Top 5：取 `v_course_overview.learner_count` 排序。
- 最近注册用户 5 条：昵称、注册时间、等级。

### 6.3 用户管理

#### 6.3.1 用户列表

列：用户 ID、昵称、手机号（脱敏）、邮箱（脱敏）、角色、状态、等级、经验、连续天数、注册时间、最后登录时间、操作（查看详情）。

筛选：

- 关键词：昵称 / 手机号 / 邮箱（模糊匹配）
- 状态：全部 / 正常（active）/ 禁用（disabled）
- 注册时间：开始日期、结束日期
- 排序：注册时间（默认倒序）、等级、经验

数据来源：`users` LEFT JOIN `user_profiles`。

#### 6.3.2 用户详情

以抽屉或独立页展示，分区块：

1. **基础资料**：`users` + `user_profiles`（昵称、手机/邮箱脱敏、角色、状态、Python 基础、等级、经验、连续天数、最长连续天数、累计学习分钟、每日目标、简介、引导完成状态、创建时间、最后登录）。
2. **学习概览**：`v_user_learning_summary`（完成课程数、完成课时数、通过题目数、累计学习分钟）。
3. **课程报名与进度**：`course_enrollments` JOIN `courses`（课程名、状态、进度百分比、报名时间、完成时间）。
4. **课时进度**：`user_lesson_progress` JOIN `lessons`（课程、课时、状态、进度、完成时间）。
5. **提交记录**：`submissions` JOIN `questions`（题目、结果、通过用例数/总用例数、运行耗时、首次是否通过、提交时间），最近 20 条。
6. **学习记录**：`learning_records`（类型、目标名称、结果、时长、学习日期），最近 20 条。
7. **每日统计**：`user_daily_stats`（日期、学习分钟、完成课时、尝试题目、通过题目、获得经验、连续天数），最近 30 天。
8. **成就**：`user_achievements` JOIN `achievements`（成就名称、说明、解锁时间）。
9. **兴趣与掌握度**：`user_interests`（兴趣、权重）、`v_mastery_target`（知识点、掌握度、尝试次数、正确次数）。
10. **消息与收藏**：`messages`（最近 10 条）、`favorites`（最近 10 条，展示目标类型与 ID）。

### 6.4 课程与内容

#### 6.4.1 课程列表 / 详情

- 列表列：课程 ID、课程编码、标题、分类、难度、评分、学习人数、课时数、总时长、状态。
- 数据来源：`v_course_overview` + `courses.status`。
- 筛选：分类、难度、状态、关键词。
- 课程详情：课程基本信息、章节与课时树（`chapters` + `lessons`）、知识点（`knowledge_points`）、题目关联（`lessons.question_id`）。

#### 6.4.2 课时详情

- 展示：课时编码、标题、类型（理论/练习）、所属章节、时长、难度、内容 JSON（按段落/代码块渲染只读视图）、初始代码、关联题目。
- 数据来源：`lessons`、`chapters`、`questions`。
- 内容 JSON 只读渲染，不提供编辑入口。

#### 6.4.3 题库列表 / 题目详情

- 列表列：题目 ID、编码、标题、难度、状态、尝试次数（来自 `v_user_question_status` 汇总）。
- 筛选：难度、状态、关键词。
- 题目详情：描述、样例输入/输出、初始代码、提交次数/通过次数、测试用例列表（`test_cases`，管理端可查看预期输出）。
- 说明：后台不提供新增/修改题目功能。

#### 6.4.4 知识点列表

- 列：ID、名称、所属课程、父知识点、难度、排序。
- 数据来源：`knowledge_points`。

### 6.5 学习数据

| 页面 | 主要列 | 筛选 | 数据来源 |
| --- | --- | --- | --- |
| 学习记录 | 用户、类型、目标名称、结果、时长、学习日期 | 用户、类型、结果、日期范围 | `learning_records` |
| 提交记录 | 用户、题目、结果、通过/总用例、耗时、首次通过、提交时间 | 用户、题目、结果、日期范围 | `submissions` |
| 课时进度 | 用户、课程、课时、状态、进度、更新时间 | 用户、课程、状态 | `user_lesson_progress` |
| 每日统计 | 用户、日期、学习分钟、完成课时、尝试题目、通过题目、经验、连续天数 | 用户、日期范围 | `user_daily_stats` |
| 掌握度 | 用户、知识点、掌握度、尝试次数、正确次数、目标难度 | 用户、知识点 | `v_mastery_target` |

所有列表每页 20 条；用户、题目等外键字段需 JOIN 出可读名称。

| 页面 | 主要列 | 说明 |


```json
{ "list": [], "total": 0, "page": 1, "pageSize": 20 }
```

## 8. 非功能需求

- **性能**：常规列表接口 P95 < 500ms；首屏 < 2s（本地环境）。
- **安全**：
  - 管理员密码只存 bcrypt 哈希于环境变量，不存明文。
  - Token 使用 HMAC-SHA256 签名，含过期时间，验证使用恒定时间比较。
  - Helmet + CORS 白名单 + 登录限流。
  - 手机号/邮箱默认脱敏。
- **兼容**：Chrome / Edge 最新版；最小宽度 1280px；表格区域横向滚动。
- **可维护**：目录结构与 003 保持一致（routes / controllers / services / middleware / config）。
- **可观测**：morgan 访问日志；错误统一 `ApiError`。

## 11. 验收标准

1. 使用后台管理员账号可登录；学生端账号不能登录后台。
2. 所有页面展示的数据均来自 MySQL `naiwa_learning`，不依赖 mock 数据。
3. 后台运行期间不产生任何 `INSERT / UPDATE / DELETE`，数据库表结构保持不变。
4. 列表筛选、分页、排序、空状态工作正常；分页默认 20 条。
5. 用户详情能正确聚合报名、进度、提交、记录、统计、成就、消息等数据。
6. 手机号、邮箱在列表中脱敏。
7. CSV 导出可用，中文无乱码。
8. 后台项目可通过 `npm install && npm run dev` 分别在 `5183` / `3101` 启动。

## 12. 明确不做

- 不新增、修改、删除任何用户、课程、题目、记录等业务数据。
- 不修改数据库表结构，不建新表、不加字段。
- 不在后台发送站内信、不批改代码、不上传头像。
- 不做学生端功能改造（学生端属于 003）。
